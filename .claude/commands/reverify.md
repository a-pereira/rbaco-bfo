Reverify RBACO-BFO, following the section "Reverifying" of `CLAUDE.md`. Its rules hold throughout: never edit `imports/`, write generated files only through their tools, and never change an expected value, a check or a test input to make a run match. When a run gives something other than what `docs/expected-results.md` states, report the difference and the output that shows it, and change nothing to make it match.

1. Read `README.md`, `CLAUDE.md` and `docs/expected-results.md`.
2. Get the tools that `docs/expected-results.md` names, and check each download's SHA-256 before using it. In a Claude Code cloud session the SessionStart hook (`.claude/hooks/session-start.sh`) has done this, outside the repository, and exported `RBACO_PY`, `RBACO_ROBOT` and `RBACO_LADR`. Confirm what it installed: `sha256sum "$RBACO_ROBOT"` gives ROBOT's SHA-256, `"$RBACO_PY" -I -c "import rdflib; print(rdflib.__version__)"` gives 7.6.0, `java -version` gives 11 or later, and `sha256sum "$RBACO_LADR"/prover9 "$RBACO_LADR"/mace4 "$RBACO_LADR"/clausetester` gives the hashes of the Linux builds. A different LADR hash means a different compiler or C library; say so and go on. If the variables are not set, build the tools as the section "Linux" of `docs/expected-results.md` says.
3. Run `sh tools/run_all.sh "$RBACO_PY" "$RBACO_ROBOT" "$RBACO_LADR" <work-dir>` in the background. The work directory must be outside the repository: $ARGUMENTS if given, otherwise a new folder in your scratchpad. The run takes about 20 minutes, 15 of them three Mace4 searches that run to their 300 s limit. Foreground commands stop at 10 minutes, so wait for the background command to finish rather than polling with `sleep`.
4. Compare each step's summary in the run's output, and its log in the work directory, with the table "run_all.sh, without --full" in `docs/expected-results.md`. For the `fol` step, compare the axioms each proof uses in `docs/fol-results.md` with the committed copy (`git diff docs/fol-results.md`). Then run `sha256sum -c MANIFEST.sha256`: only the files and lines that the section "What a run may change" names may differ.
5. Run the two `check_hand_model.py` commands in `README.md`, with `"$RBACO_PY" -I -X utf8` as the Python, `"$RBACO_LADR"/clausetester` as clausetester and an output folder outside the repository, and compare them with the section "Hand-specified models".
6. Report each expected result as matched or not, with the value measured, and the tools used, with their versions and SHA-256. Say plainly what could not be run or checked. Leave the regenerated files in place and commit nothing unless asked.
